HTML & CSS Foundations

A complete walkthrough of how web pages are built and styled — from your first tag to the box model and CSS cascade, with real, live-rendered examples throughout.

Concept Getting Started with Web Development

Every website is built from three layers working together: HTML gives a page its structure and content (headings, paragraphs, images), CSS controls how that structure looks (colors, spacing, layout), and JavaScript adds behavior (clicks, animations, logic). This course focuses on the first two — HTML and CSS — which are enough to build a fully-styled, static website.

To write HTML and CSS you need only a text editor and a browser. Files are plain text saved with .html or .css extensions; the browser reads them top to bottom and renders the result.

Concept Introduction to GenAI in Web Development

Generative AI tools (like Claude) can scaffold HTML/CSS structure, explain error messages, suggest layout approaches, and generate placeholder content — turning a blank page into a working draft in seconds. The skill to build alongside this is reading and understanding the code AI produces, not just accepting it — so you can adapt it and know when it's wrong.

Concept Coding Platform Walkthrough

Most beginner platforms give you three panes: an HTML editor, a CSS editor, and a live preview that updates as you type. Some (like CodePen or your browser's dev tools) also add a console for JavaScript errors. The core workflow is always: write → save → refresh → observe.

HTML Introduction to HTML

HTML (HyperText Markup Language) describes content using elements, written as tags. Most elements have an opening tag, content, and a closing tag: <p>text</p>. Every HTML document follows the same skeleton:

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>My Page</title>
  </head>
  <body>
    <h1>Hello, world</h1>
    <p>This is my first paragraph.</p>
  </body>
</html>

<!DOCTYPE html> tells the browser to use modern HTML rules. <head> holds metadata (not visible content); <body> holds everything the visitor sees. Tags can carry attributes — extra info inside the opening tag, like lang="en" or src="cat.jpg".

HTML Introduction to HTML5

HTML5 is the current standard. It added native support for audio/video, form validation, and — most importantly for structure — semantic elements, so pages no longer rely on generic <div> soup to describe their layout.

HTML HTML Semantic Elements

Semantic elements describe the meaning of a region, not just its box. This helps browsers, search engines, and screen readers understand your page.

<header>Site logo & nav</header>
<nav>...</nav>
<main>
  <article>
    <h1>Post title</h1>
    <section>Content section</section>
  </article>
  <aside>Related links</aside>
</main>
<footer>Copyright</footer>

Compare that to using only <div class="header"> everywhere — it works visually, but tells assistive tech and machines nothing about the page's shape.

HTML Void Elements & Lists

Void elements have no closing tag and no content — they're self-contained: <img>, <br>, <hr>, <input>, <meta>.

Lists come in two kinds: unordered (<ul>, bullets) and ordered (<ol>, numbers), each containing <li> items.

<img src="cat.jpg" alt="A cat">
<ul>
  <li>Milk</li>
  <li>Eggs</li>
</ul>
<ol>
  <li>Preheat oven</li>
  <li>Mix batter</li>
</ol>

HTML HTML Hyperlinks

Links use the <a> tag with an href attribute pointing to a destination — another page, a section on the same page (#id), an email (mailto:), or a file.

<a href="https://example.com">Visit site</a>
<a href="#pricing">Jump to pricing</a>
<a href="mailto:hi@site.com">Email us</a>
rendered
Visit site

Concept Website: Behind the Scenes

When you type a URL, your browser sends a request to a server, which sends back HTML. The browser parses that HTML into the DOM (Document Object Model), fetches linked CSS and applies styles to build the render tree, then paints pixels to the screen. Any linked JavaScript runs and can modify the DOM afterward, which triggers a re-render.

CSS Introduction to CSS — Parts 1–3

Part 1 — Syntax. CSS rules pair a selector (what to style) with a declaration block (how to style it), made of property:value pairs.

selector {
  property: value;
  property: value;
}

p {
  color: navy;
  font-size: 18px;
}

Part 2 — Three ways to apply CSS. Inline (on the element, avoid this), internal (a <style> tag in <head>), and external (a separate .css file linked via <link> — the standard, scalable approach).

<link rel="stylesheet" href="styles.css">

Part 3 — Common properties. color, background, font-size, font-weight, text-align, margin, padding, border, display cover most day-to-day styling.

CSS CSS Selectors & Inheritance

p            /* type: all <p> elements     */
.card        /* class: any el. with class="card" */
#logo        /* id: the one el. with id="logo"    */
p.intro      /* combined: <p> with class intro */
div p        /* descendant: any <p> inside a <div> */

Inheritance: some properties (mainly text-related — color, font-family) pass automatically from parent to child unless overridden. Layout properties like border or margin do not inherit.

CSS More CSS Selectors

ul > li          /* direct child       */
h2 + p           /* immediately after  */
a:hover          /* pseudo-class: on hover */
li:first-child   /* pseudo-class: position */
p::first-line    /* pseudo-element: part of an element */
[type="text"]    /* attribute selector */

CSS CSS Specificity & Cascade

When multiple rules target the same element, the browser picks a winner using specificity — roughly: inline styles > IDs > classes/attributes > type selectors. If specificity ties, the rule that appears last in the CSS wins (the "cascade"). !important overrides normal specificity entirely and should be used sparingly.

#spec-target   { color: gray;   }  /* id: wins over class */
.spec-cls#spec-target { color: orange; } /* id+class: more specific still */
p.spec-cls     { color: blue !important; } /* !important overrides all */
rendered — final color is decided by specificity + !important

CSS More CSS Concepts

Beyond selectors and boxes, everyday CSS relies on: display (block / inline / flex / grid), position (static / relative / absolute / fixed), units (px, %, rem, vh/vw), and flexbox for one-dimensional layouts:

.row { display: flex; gap: 12px; justify-content: space-between; }

CSS CSS Box Model — Parts 1–2

Every HTML element is a rectangular box made of four layers, from the inside out: content → padding → border → margin. Padding is space inside the border; margin is space outside it, separating the box from its neighbors.

.box {
  width: 200px;
  padding: 16px;
  border: 6px solid orange;
  margin: 20px;
}
rendered — orange = border, blue = content, the tan area is margin space
content

Part 2: the total rendered size of a default box is width + padding + border (margin sits outside and only affects spacing to neighbors) — which is exactly the problem box-sizing solves next.

CSS Box Sizing

By default (box-sizing: content-box), padding and border are added on top of the width you set — a 160px box with 16px padding and 8px border actually renders 208px wide. box-sizing: border-box instead makes width include padding and border, so the box stays exactly the size you declared.

.content-box { box-sizing: content-box; width: 160px; } /* grows beyond 160px */
.border-box  { box-sizing: border-box;  width: 160px; } /* stays 160px total */

* { box-sizing: border-box; } /* common reset, applied to everything */
rendered — both boxes are declared width:160px, same padding/border

CSS Sizing Elements & Handling Overflow

When content is bigger than its box, overflow decides what happens: visible (default, spills out), hidden (clipped), scroll/auto (scrollbars appear as needed).

.box { width: 180px; height: 70px; overflow: hidden; }

Concept Leveraging GenAI for Accelerated Learning

Use AI to shorten the feedback loop: ask it to explain why a snippet behaves a certain way, generate small variations of a concept to compare side by side, or quiz you on selectors and specificity until it's automatic. The highest-leverage habit is asking "why" after every answer, not just copying the fix.

Concept Leveraging GenAI for Debugging & Building

When a layout breaks, paste the relevant HTML + CSS and the actual vs. expected result — AI is much more accurate with that context than with "my CSS is broken." For building, use AI to scaffold a first draft fast, then take over to refine details and make sure you understand every rule it wrote.
